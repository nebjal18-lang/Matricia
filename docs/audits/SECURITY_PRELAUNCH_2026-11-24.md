## Complément sans prestataire de paiement choisi

- **Authentification, élevé :** la vérification du code OTP réserve désormais un quota persistant distinct de l'envoi (5 tentatives par identifiant et 20 par IP sur 15 minutes dans le RPC existant). Elle échoue fermée si le quota est indisponible. Les refus et les codes incorrects/expirés sont journalisés par catégorie, sans courriel ni code OTP. L'interface affiche le message de limitation existant. Les tests de refus et d'indisponibilité passent ; le réglage GoTrue hébergé reste non vérifié.
- **Configuration HTTPS, élevé :** un build marqué `VERCEL_ENV=production` ou `APP_ENV=production` refuse désormais `NEXT_PUBLIC_APP_URL` absent, en HTTP, avec identifiants, port non standard, chemin ou paramètres. Ce contrôle garantit une origine applicative de production canonique dans la configuration ; la redirection HTTP réelle doit encore être testée sur le domaine déployé.
- **Paiement, critique :** le garde existant interdisait déjà le prestataire `DEMO` en production. La fabrique CMI/PayPal tient maintenant compte de `VERCEL_ENV=production` même si `APP_ENV` est erronément `staging`, et refuse leur mode test ou un paiement live non activé. Aucun prestataire n'a été choisi ni activé ; le PSP et les webhooks réels restent à prouver après ce choix.

Validation Node 22.23.5 : 31 tests ciblés de connexion et d'interface OTP réussis ; 53 tests ciblés de connexion et de configuration d'environnement réussis ; 22 tests de passerelles de paiement réussis ; typecheck `apps/web` et `packages/infrastructure` réussis. Aucun test de base, PSP externe ou déploiement de production n'a été exécuté pour ce complément. Le verdict reste **NO-GO**.
