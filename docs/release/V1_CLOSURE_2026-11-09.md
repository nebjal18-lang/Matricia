### Complément CI et fiabilité des scans

La dépendance `server-only` est déclarée explicitement. Vitest simule uniquement ce marqueur de chargement pour ses tests serveur, sans remplacer globalement les repositories, les permissions ou les clients de données. Le build Next conserve son contrôle de frontière serveur/client.

Le contexte client contrôle d’abord le droit de sélectionner le tenant. Une projection d’organisation autorisée mais invalide devient `CLIENT_CONTEXT_UNAVAILABLE`, sans basculement silencieux sur une autre organisation. Les fixtures de tests reflètent désormais la jointure réelle.

Le scan dynamique exige HTTP 200, titre métier, absence de panne et maintien de l’origine, de la route et du contexte organisation/franchise. Les deux refus fiscaux attendus exigent précisément `FORBIDDEN` et restent distingués d’une page métier réussie. Une redirection de connexion, un refus MFA, une configuration manquante ou une 404 ne peuvent plus produire un faux succès.

La politique CSP accepte le POST CMI uniquement vers l’origine HTTPS configurée et explicitement autorisée. La recette Chromium intercepte toutes les requêtes : aucune passerelle réelle n’est contactée.
