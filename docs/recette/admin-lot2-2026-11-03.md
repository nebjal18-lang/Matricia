# Administration — lot 2 : dossiers et suivi des actions

Branche : `codex/admin-lot2-20261103`, basée sur `2075da4` du lot 1 (PR #4). Ce lot s’ajoute au premier ; il ne le fusionne pas.

## Problèmes et corrections

Le résolveur de dossiers regroupait des types de ressources distincts sous les mêmes routes. Un identifiant de devis était envoyé dans `demandes`, un résultat de matching également, un jalon dans `missions` et un avenant dans `contrats`. Or les lecteurs comparent les identifiants propres à chaque collection : aucune résolution implicite de parent n’existe.

Les détails utilisent désormais un mapping explicite : QUOTE → devis, MATCHING_RUN → matching, MILESTONE/MISSION_MILESTONE → jalons, AMENDMENT/CONTRACT_AMENDMENT → avenants. Les types diagnostic et versions documentaires correspondent aux identifiants réellement projetés. RFQ, livrables, versions de devis/contrats et familles documentaires sans parent résolu ouvrent une file métier ; leur identifiant n’est plus réinterprété comme celui du parent. Les types inconnus ne déclenchent pas de détail deviné. Les segments sont encodés et les segments vides, `.` et `..` sont refusés comme cibles de détail.

Les cartes et la recherche emploient le même résolveur, en transmettant uniquement le contexte organisation. Les paramètres de recherche et de pagination du centre ne sont pas propagés vers les autres modules. Le formulaire de filtre des approbations préserve `organizationId` et `q`, et remet la pagination à la première page.

Les commandes prise en charge, résolution, demande d’action, décision et balayage des exceptions rafraîchissent le centre une seule fois après un reçu RPC valide. Une session absente, un refus, un conflit ou une réponse invalide ne déclenche pas de rafraîchissement réussi. Les contrôles d’autorisation, versions attendues, motifs et clés d’idempotence sont conservés.

## Limites

Aucune migration SQL, modification RLS, donnée distante ou configuration de production. Les tests des actions utilisent des réponses RPC contrôlées ; ils vérifient le raccord et les refus, sans exécuter de commande métier distante. La recette Admin AAL2 native et les RPC sur base de test restent nécessaires. Les traitements de confidentialité/effacement et les exports volumineux déjà recensés ne sont pas déclarés terminés.
